# Conversation Database Setup for RAG Companion

This document explains how to set up and use the conversation database system for persistent conversation storage and retrieval.

## 🎯 Overview

The conversation database system provides:
- **Persistent Storage**: All conversations are saved to PostgreSQL with pgvector
- **Session Management**: Automatic conversation session creation and tracking
- **Content Organization**: Text, multimedia, and MCP tool usage tracking
- **Search & Retrieval**: Find past conversations and build context
- **Analytics**: Track conversation patterns and usage statistics

## 🗄️ Database Schema

### Core Tables

#### `conversation_sessions`
Stores conversation session metadata:
```sql
CREATE TABLE conversation_sessions (
    session_id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    started_at TIMESTAMPTZ DEFAULT NOW(),
    ended_at TIMESTAMPTZ,
    metadata JSONB
);
```

#### `conversation_turns`
Stores individual conversation exchanges:
```sql
CREATE TABLE conversation_turns (
    turn_id TEXT PRIMARY KEY,
    session_id TEXT NOT NULL,
    user_id TEXT NOT NULL,
    turn_index INTEGER NOT NULL,
    user_message TEXT,
    assistant_response TEXT,
    retrieved_chunks TEXT[],
    created_at TIMESTAMPTZ DEFAULT NOW(),
    metadata JSONB,
    FOREIGN KEY (session_id) REFERENCES conversation_sessions(session_id)
);
```

#### `conversation_content`
Stores detailed content within turns:
```sql
CREATE TABLE conversation_content (
    content_id TEXT PRIMARY KEY,
    turn_id TEXT NOT NULL,
    user_id TEXT NOT NULL,
    content_type TEXT NOT NULL, -- 'text', 'image', 'audio', 'video', 'file'
    content_data TEXT, -- For text content
    multimedia_id TEXT, -- Reference to multimedia_content table
    content_order INTEGER, -- Order within the turn
    is_user_content BOOLEAN, -- True if from user, False if from assistant
    mcp_tool_used TEXT, -- If content was generated by MCP tool
    tool_parameters JSONB, -- Parameters used by the MCP tool
    created_at TIMESTAMPTZ DEFAULT NOW(),
    metadata JSONB,
    FOREIGN KEY (turn_id) REFERENCES conversation_turns(turn_id),
    FOREIGN KEY (multimedia_id) REFERENCES multimedia_content(content_id)
);
```

## 🚀 Setup Instructions

### 1. Environment Configuration

Set your Railway PostgreSQL connection string:
```bash
export DATABASE_URL="postgresql://username:password@host:port/database"
```

Or create a `.env` file:
```env
DATABASE_URL=postgresql://username:password@host:port/database
```

### 2. Database Initialization

The database tables are automatically created when the service starts. The system will:
- Connect to PostgreSQL
- Create the `vector` extension if not exists
- Create all required tables
- Set up proper indexes

### 3. Verify Setup

Check the health endpoint:
```bash
curl http://localhost:8000/health
```

Expected response:
```json
{
  "database_available": true,
  "vector_search": "postgresql_pgvector",
  "conversation_manager": "active"
}
```

## 📱 API Endpoints

### Conversation Management

#### Get User Conversations
```bash
GET /conversations/{user_id}?limit=10
```
Returns conversation history for a user.

#### Get User Sessions
```bash
GET /conversations/{user_id}/sessions?limit=10
```
Returns conversation sessions for a user.

#### Get Session Details
```bash
GET /conversations/session/{session_id}
```
Returns detailed information about a conversation session.

#### Get Session Turns
```bash
GET /conversations/session/{session_id}/turns
```
Returns all turns for a conversation session.

#### Search Conversation History
```bash
GET /conversations/search/{user_id}?query=machine+learning&limit=5
```
Search through conversation history for a user.

### Analytics

#### User Analytics
```bash
GET /conversations/analytics/{user_id}?days=30
```
Get conversation analytics for a specific user.

#### Global Analytics
```bash
GET /conversations/analytics?days=30
```
Get global conversation analytics.

### Session Management

#### End Session
```bash
POST /conversations/session/{session_id}/end
```
End a conversation session.

#### Delete Session
```bash
DELETE /conversations/session/{session_id}
```
Delete a conversation session and all related data.

## 🔧 Usage Examples

### Python Client Example

```python
import aiohttp
import asyncio

async def test_conversation_api():
    async with aiohttp.ClientSession() as session:
        # Get conversation history
        async with session.get('http://localhost:8000/conversations/user123') as resp:
            history = await resp.json()
            print(f"Found {history['total_conversations']} conversations")
        
        # Get session analytics
        async with session.get('http://localhost:8000/conversations/analytics/user123?days=7') as resp:
            analytics = await resp.json()
            print(f"User had {analytics['analytics']['total_sessions']} sessions in 7 days")

# Run the example
asyncio.run(test_conversation_api())
```

### cURL Examples

```bash
# Get conversation history
curl "http://localhost:8000/conversations/user123?limit=5"

# Search for conversations about "machine learning"
curl "http://localhost:8000/conversations/search/user123?query=machine%20learning&limit=3"

# Get user analytics for last 30 days
curl "http://localhost:8000/conversations/analytics/user123?days=30"
```

## 📊 Data Flow

### 1. Conversation Start
```
User sends message → System creates/gets session → Stores turn → Stores content
```

### 2. Content Storage
```
Text content → conversation_content table
Multimedia → multimedia_content table + conversation_content reference
MCP tools → conversation_content with tool metadata
```

### 3. Retrieval
```
Query → Search conversation_content → Join with turns/sessions → Return structured data
```

## 🔍 Monitoring and Debugging

### Check Database Status
```bash

curl http://localhost:8000/health

# Database info
curl http://localhost:8000/admin
```

### Common Issues

#### Connection Errors
- Verify `DATABASE_URL` is correct
- Check if Railway PostgreSQL is running
- Ensure network connectivity

#### Table Creation Errors
- Check if pgvector extension is available
- Verify database user has CREATE privileges
- Check PostgreSQL version compatibility

#### Performance Issues
- Monitor query execution times
- Check database connection pooling
- Consider adding more indexes for large datasets

## 📈 Scaling Considerations

### Database Optimization
- Add indexes for frequently queried fields
- Use connection pooling for high concurrency
- Monitor query performance and optimize slow queries

### Storage Management
- Implement data retention policies
- Archive old conversations to cheaper storage
- Use partitioning for large tables

### Caching
- Cache frequently accessed conversation data
- Use Redis for session state
- Implement query result caching

## 🔐 Security Considerations

### Data Privacy
- Encrypt sensitive conversation data
- Implement user data deletion (GDPR compliance)
- Audit access to conversation data

### Access Control
- Implement user authentication
- Restrict access to conversation data by user
- Log all data access attempts
